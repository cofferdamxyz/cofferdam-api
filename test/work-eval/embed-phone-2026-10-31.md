# The v2 embedder on the phones against the Mac, 2026-10-31

Generated by `test/workEmbedPhone.eval.test.ts` (texts and scoring: `test/work-eval/embedPhone.ts`). 2298 synthetic or public texts, embedded by each phone's app through the reader benchmark's embed mode (cofferdam-app `readerBench.ts`: the app's own `embed`, the role's prompt and the white space as the app will send them to the Work routes) and by the Mac with the same pinned file (`litertlm:litert-community/embeddinggemma-2-text-270m-litert-lm:embeddinggemma-2-text-270m.litertlm`, LiteRT-LM's Python API on the CPU). Rule (2)'s bar: every phone vector within cosine 0.9998 of the Mac's, and each one a vector the plane takes (`readClientVector`: 768 finite values at unit length). Decisions on the Mac's v2 replica (229,654 labels), as the plane reads the nearest labels at each step: each claim's 20 nearest labels of its kind (a certificate against the skills, since no certificate token has a vector), each token at its best; the best token taken at τ_auto 0.96 on its best score through a label in the claim's language or English, Clef's band from τ_low 0.81 with the 5 tokens it would be shown, and under τ_low nothing the vector chose (the step after reads the string and its English name); each sentence's ten nearest listing texts of set 3 and their side of the tier-2 floor 0.65, which recall reads on a listing's cosine and no snap reads. A different step passes only when both scores sit within 0.001 of the threshold between them, a different token or candidate only on a tie within 0.001.
