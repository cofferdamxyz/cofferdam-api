# AGENTS Instructions

## Scope

Cloudflare Workers API plane for Cofferdam.

## Runtime

- TypeScript, `wrangler`, viem, @noble/curves.
- Do not hardcode `account_id` in `wrangler.jsonc`.

## Key Services

- `src/services/sessionAttestation.ts` verifies `csa1:` passkey-signed envelopes from `@cofferdam/sdk`, v1 and the device-bound v2 with its per-request proof (workspace decision 0055). Must stay byte-compatible with SDK `sessionAttestation.ts` and `popProof.ts`; `test/fixtures/sdk-attestations-v2.json` holds real SDK tokens and proofs, and both repositories pin one digest vector.
- `src/services/sessionGate.ts` is the one session check the chat (fast), the bind-bundle pickup (slow) and the ceremony's passkey lane (slow) share: v2 with its `DPoP` proof, each `jti` claimed once in the device key's `PopReplayDO` (`popReplayStore.ts` holds the SQL, run on `node:sqlite` in the tests; unbound outside development answers `503 replay_store_unavailable`), `401 step_up_required` for a fast token on a slow route, and v1 bearer tokens until `CSA1_V1_ACCEPTED` is `"false"`.
- `src/services/activity.ts` fetches USDC Transfer events per chain (workspace decision 0032): Base Sepolia (84532) reads the CDP-webhook-fed `ActivityDO` record (`activityStore.ts`, `activityDO.ts`, `POST /v1/activity/webhooks/cdp`) and scans older blocks with `activityScan.ts` in chunks of `ACTIVITY_LOG_RANGE` (200: the public node refuses 202), where a refused call is an error, never an empty list; Base mainnet (8453) uses the SQD Portal Stream API (public, unkeyed) and falls back to the chunked scan on 429/529/502/503. `ACTIVITY_LIVE=1 yarn vitest run test/activity.live.test.ts` checks the scan against the public Sepolia node.
- `src/env.ts` declares optional `POLIS_DATABASE_URL` and `ACTIVITY_DATABASE_URL` as future fallbacks.
- `src/routes/self.ts` + `src/services/selfBind.ts` receive Self.xyz's relayer proof (`POST /v1/self/verify`), pre-flight `NullifierRegistry`, call `ATTESTER.signBind` (Celo-gated) or, for a passport bound to another account, read `rebindCount` and call `ATTESTER.signRebind` (bundle `kind: 'rebind'`, decision 0022), and store the bundle in the per-account `BindBundleDO` Durable Object (decision 0010) for `GET /v1/self/bind-bundle/:account` (csa1-gated outside development). The endpoint must stay on the `cofferdam.xyz` host (zone route): only the host enters the immutable scope.
- `src/routes/ceremony.ts` + `src/services/ceremony.ts` issue the decision 0016 ceremony co-sign (`POST /v1/ceremony/first-high`): the gate is pure and tested against fakes; chain reads and the `ATTESTER.signCeremony` call are injected.
- `src/routes/aa.ts` + `src/services/userOp.ts` relay the app's signed ERC-4337 ops (`POST /v1/aa/user-operation`): policy (our paymaster, our factory in `initCode`, gas/fee/prefund caps) → `handleOps` simulation from the relayer → the per-sender `AA_RELAY_RL` → submission with `RELAYER_PRIVATE_KEY`. Like chat, the pickup, the ceremony and the relay run a global brake and a per-IP ceiling (`*_IP_RL`) first and count the per-account bucket only once their gate passes: account addresses are public. The first op of an account carries `initCode`, so this is also deployment (decision 0012).
- `src/routes/enterprise.ts` + `src/services/company.ts` + `src/services/companyLinks.ts` implement the domain-anchored `companyAnchor` resolver and `CompanyConsumerLink` grants. Link routes return `503 link_store_unprovisioned` until the `LINKS` KV namespace is created.
- `src/services/chat/facts.generated.ts` is the product-facts block the answer models' system message carries (workspace decision 0048), compiled from the workspace's `skills/*/SKILL.md` by `scripts/compile-skills.mjs` (run it and commit the output whenever a skill changes); `test/facts.test.ts` fails on drift, on more than 800 prompt tokens, and on jargon or internal names in a fact.
- `src/services/inference` is the only way to Workers AI (`test/inference.test.ts` fails on `env.AI` anywhere else): op classes with model pins (`AI_PINS` KV, then `CHAT_*_MODEL` or `WORK_*_MODEL`, then the default), an `op:` tag per call, timeouts, and the strict gateway with no log when `AI_GATEWAY_ID` is set.
- `src/routes/work.ts` + `src/services/work/` are the Work parser's cloud executor (workspace decisions 0020 and 0021, `docs/product/engine.md`): `POST /v1/work/classify` (the document type, one `clef-flash` call on `work-classify`) and `POST /v1/work/extract` (one de-identified block into a `cofferdam.cv.v1` fragment on `work-extract`, then `work-extract-fallback`); `intent.ts` parses a hirer's sentence on `work-intent` (inside `POST /v1/jobs/intent`). `blocks.ts` re-checks every block before any hosted call and fails closed; `fields.ts` holds the typed fields, the request per model family (Clairic, Workers AI JSON mode, the OpenAI JSON-schema wrapper) and the span validation; names come from the block's placeholders, never from a model. Outside development both routes answer `503 strict_gateway_required` until `AI_GATEWAY_ID` is set (decision 0021 (f)). The gate and the caps are the chat's, in the chat's order, in `src/routes/workGate.ts`, the one admission every Work route shares; every call is metered to the account and `plane:global` with no turn, priced from `usage.neurons` when reported, else `MODEL_PRICES` (`meter.ts`), and a call that throws or reports no tokens at its estimated input (`estimatedUsage`, characters over four). `test/work.eval.test.ts` (opt-in, `WORK_EVAL=1`) compares extractors on the synthetic fixtures in `test/fixtures/work/`; no real personal data enters the repository or a model.
- `src/services/work/registry.ts` is the token registry (workspace decision 0018): D1 `WORK_DB` (`cofferdam-work`, migrations in `migrations/work/`, run on `node:sqlite` by the tests through `test/fixtures/work/d1.ts`) and Vectorize `TOKEN_REGISTRY` (`token-registry-v1`), both commented in `wrangler.jsonc` until the founder creates them. Retrieve-then-choose: an exact label, else `work-embed` (`bge-m3`) candidates, τ_auto, a Clef `choice` by candidate key in the band (`work-adjudicate`), and below it, or on Clef's own none at its floor, a `pending` mint named by `work-pivot`; a Clef call that fails or answers nothing is no token, one below its floor can only reach an existing token through the pivot, and certificates never mint. No model writes an ESCO or ISCO code: `esco.ts` reads them from the official CSV export, and `test/esco.import.test.ts` (opt-in, `ESCO_IMPORT=1`) writes the SQL and NDJSON the founder loads. Certificates come only from the curated seed, `certificates.json`, bundled with the Worker and read by `certificates.ts` (E10): a jurisdiction suffix where a licence is local; levels and modules as metadata of one token that become facet tokens of a listing's exact list (`cert:nccco-rigger/level-2`; a claim holds its level and every level below and keeps the lower of two, a requirement names what it needs and keeps the higher); specific names, and shared ones (a state, NCCCO, TDLR) that need one of the seed's distinctive words beside them; excludes and not-held words, negations and a claim's validity date this month or before included, that refuse before any model; and hirer phrases read as the licence of the job's region (`SnapInput.region`). A credential fits a string only when every word left after its level, modules and fillers (and, for a claim, its details, a course's hours unless its levels are hours, and a validity date ahead) is its own, so a grade or module the seed cannot read is no token; in the band Clef chooses among at most three candidates that fit, at the unchanged floor, and never reads a level. `test/workCertificates.test.ts` holds the seed to its own rules; `test/certificates.import.test.ts` (opt-in, `CERT_IMPORT=1`) writes its SQL and NDJSON. `test/workRegistry.eval.test.ts` (opt-in) measures snaps on the synthetic occupation and skill seed and the certificate seed, a certificate as a worker's claim or a hirer's requirement.
- `src/services/work/listings.ts`, `recall.ts`, `hire.ts` and `bloom.ts` are S4 to S7 (workspace decision 0019): a listing publishes into Vectorize `JOBS_LISTINGS` (`jobs-listings-v1`, commented until created) in the namespace of its coarse region and scope, with metadata `{v, region, scope, tier, bloom, model}` only (never a position, a cell or an owner) and its exact token list in D1 `listings` (`migrations/work/0002_listings.sql`), keyed by Work pseudonym and profile id, at most `MAX_WORK_PROFILES` (3, workspace decision 0060) per pseudonym, enforced again by the record's conditional write, which goes before the vector; recall fans one 50-result query out per namespace, gates by the Bloom filter, confirms certificates against the exact list, drops the pseudonym it is told to exclude (the hirer's own) and keeps one listing per pseudonym; `hire.ts` turns a hirer's sentence into that intent: the block tripwire and a check of its language and regions run before any hosted call, a first Clef call checks the request (harmful, injection) and its scope before anything is extracted, failing closed, then Clef chooses the needed tokens among the registry's (an answer to none of them stops the plan), a hirer's words never mint, and the job is Instant only when every stated requirement is gated. `clef.ts` is the one catalogue of these Clef patterns, with fail-closed readers; `test/workClef.eval.test.ts` (opt-in) calibrates them. Every one of these returns the hosted calls it made, and a store or index failure throws a `WorkCallsError` that carries them, so its route meters them either way. `test/workRecall.test.ts` runs it on node:sqlite and an in-memory index that enforces Vectorize's 50; `test/workRecall.eval.test.ts` (opt-in) runs one hirer query with the real models.
- `src/routes/workListing.ts` (`PUT` and `DELETE /v1/work/listing`: Looking for work on and off, per Work Profile) and `src/routes/jobs.ts` (`POST /v1/jobs/intent`: the hirer query) serve those services through `src/routes/workGate.ts`, on `WORK_RL` and `WORK_IP_RL` (`/v1/jobs` on its own `jobs:` keys); a listing taken down runs no model, so it skips the strict gateway and the caps, and counts on keys of its own (`work-off:`), so no other Work traffic can use up a withdrawal. The routes derive the account's Work pseudonym on every request (`services/work/pseudonym.ts`: HMAC-SHA-256 under the secret `WORK_PSEUDONYM_KEY`, `503 pseudonym_key_unprovisioned` without it; rotating the key strands every listing under the old pseudonyms, and none can be re-keyed in place since no record holds its account, so a rotation takes every listing down first and the phones publish again) and never store, log or answer the account beside a listing. A listing publishes no more personhood than `NullifierRegistry.isAccountBound` shows (1 bound, else 0; `503 binding_check_unavailable` when Base cannot be read). The hirer query answers the plan and the finalists as counts only (how many, by gate tier and by personhood tier), never a card per finalist: a score, tier or token list per finalist would let answers be joined to follow a worker or link their profiles (workspace decision 0060 (5)). The hirer's own listings are left out. Each answers `503 work_db_unprovisioned`, `token_registry_unprovisioned` or `jobs_listings_unprovisioned` while a store it needs is unbound (`services/work/stores.ts`). `test/workListingRoutes.test.ts`, `test/jobsRoutes.test.ts` and `test/workProfiles.test.ts` run them on node:sqlite and the in-memory indexes (`test/fixtures/work/world.ts`).
- `src/routes/chat.ts` + `src/services/chat/` run one Cofferdam Cloud chat turn (`POST /v1/chat`, workspace decision 0037): a global brake and `CHAT_IP_RL`, csa1 and an active High gate remembered for five minutes (`authorityMemo.ts`, shared with `/v1/work` and `/v1/jobs`, which also spend only Workers AI), the per-account `CHAT_RL` after the gate, a `clef-flash` router (`router.ts`) and the routed models (`run.ts`: the everyday answer starts with the router and is held until it clears the turn; `choices` when unsure; the body's `tier: "thinking"` answers on `chat-reasoning`, DeepSeek V4.1 Flash at low effort, high above `CHAT_THINKING_HIGH_FLOOR` on Clef's reasoning score, with no early answer and one retry when the first attempt has sent nothing within 15 s), streamed as server-sent events. The text never reaches a log. Each finished turn is metered per account and month in `ChatUsageDO`, and per month and model beside it with the router left out (`chatUsageStore.ts` holds the SQL, run on `node:sqlite` in `test/chatUsage.test.ts`; `chatUsageDO.ts`; priced from the neurons the model reports, else `MODEL_PRICES` in `services/inference`; the router from Clef's reported tokens, else its state's characters over four; model rows with no turns, the Work routes' document calls, stay out of the cost of a turn in `capEstimate`) through `waitUntil`; `CHAT_MONTHLY_USD_CAP` (dollars of estimated cost, not tokens) refuses an account with `429 fair_use_cap` and `AI_MONTHLY_BUDGET_USD` (the plane-wide row `plane:global`, which every hosted AI op must also record to) refuses everyone with `503 ai_budget_reached`, both before any model call, and `GET /v1/chat/usage` answers the month, its `models` most-used first and what is left of the cap in dollars and estimated turns, behind the same gate.
- `xmtp/` is the XMTP operator (workspace decision 0042), three Workers that deploy on their own and are not the plane: `backend/` (the XMTP 8 backend container, `backend.toml`, ingress slot `INGRESS=off` until the inbound-TCP beta), `push-relay/` (decision 0040: sealed tokens, APNs alert or FCM data, no storage, no `console`, observability off; `test/xmtp/pushRelay.test.ts` enforces it) and `cleanup/` (hourly expired-envelope deletion; its retention vars mirror `backend.toml` `[retention]`, checked by `test/xmtp/config.test.ts`; `src/health.ts` checks the backend's schema first, stores it under the KV key `health`, skips the run until the tables exist, and answers `GET /health`, reachable only through `wrangler dev --remote`). The backend's database is a direct Postgres 17+ endpoint, never Hyperdrive or a transaction pooler; only `cleanup/` uses Hyperdrive. `XMTP_CLEANUP_PG_URL=postgres://…/xmtp_cleanup_test yarn vitest run test/xmtp` runs the cleanup SQL against a migrated XMTP schema. On a backend version bump re-check `cleanup/src/sql.ts` against its migrations.
- The planned Assignment service is generic, account-pseudonym keyed, local-first, and escrow-optional. Port structural behavior from OffshoreSync `WorkAssignment`/`ScheduleOverride`; do not import Mongo IDs or maritime social dispatch into the plane.

## Validation and deploys

- `yarn test`, `yarn typecheck` (the Worker, then the Worker plus tests through `tsconfig.test.json`) and `yarn lint` (typescript-eslint, type-checked; `eslint.config.mjs`) must pass. The Mac lanes (`src/routes/chat.ts`, `src/services/chat/*`, `src/services/inference/*`) are downgraded to warnings in `eslint.config.mjs` until they are cleaned on the Mac; delete that block then.
- Verify on-chain authority config matches SDK encoding before deploying.
- Deploys run only from the Mac with the workspace `.envrc` loaded (`direnv exec .. yarn deploy`), never from a cloud session; when a contract pin moves, deploy the attester first. Runbook: `docs/runbooks/cloudflare-deploys.md` in the workspace. `src/chain/deployments.ts` mirrors `base-contracts/deployments/baseSepolia.json`.
- Design: `docs/architecture/plane.md` in the workspace.
