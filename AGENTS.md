# AGENTS Instructions

## Scope

Cloudflare Workers API plane for Cofferdam.

## Runtime

- TypeScript, `wrangler`, viem, @noble/curves.
- Do not hardcode `account_id` in `wrangler.jsonc`.

## Key Services

- `src/services/sessionAttestation.ts` verifies `csa1:` passkey-signed envelopes from `@cofferdam/sdk`, v1 and the device-bound v2 with its per-request proof (workspace decision 0055). Must stay byte-compatible with SDK `sessionAttestation.ts` and `popProof.ts`; `test/fixtures/sdk-attestations-v2.json` holds real SDK tokens and proofs, and both repositories pin one digest vector.
- `src/services/sessionGate.ts` is the one session check the chat (fast), the bind-bundle pickup (slow) and the ceremony's passkey lane (slow) share: v2 with its `DPoP` proof, each `jti` claimed once in the device key's `PopReplayDO` (`popReplayStore.ts` holds the SQL, run on `node:sqlite` in the tests; unbound outside development answers `503 replay_store_unavailable`), `401 step_up_required` for a fast token on a slow route, and v1 bearer tokens until `CSA1_V1_ACCEPTED` is `"false"`.
- `src/services/activity.ts` fetches USDC Transfer events per chain (workspace decision 0032): Base Sepolia (84532) reads the CDP-webhook-fed `ActivityDO` record (`activityStore.ts`, `activityDO.ts`, `POST /v1/activity/webhooks/cdp`) and scans older blocks with `activityScan.ts` in chunks of `ACTIVITY_LOG_RANGE` (200: the public node refuses 202), where a refused call is an error, never an empty list; Base mainnet (8453) uses the SQD Portal Stream API (public, unkeyed) and falls back to the chunked scan on 429/529/502/503. `ACTIVITY_LIVE=1 yarn vitest run test/activity.live.test.ts` checks the scan against the public Sepolia node.
- `src/env.ts` declares optional `POLIS_DATABASE_URL` and `ACTIVITY_DATABASE_URL` as future fallbacks.
- `src/routes/self.ts` + `src/services/selfBind.ts` receive Self.xyz's relayer proof (`POST /v1/self/verify`), pre-flight `NullifierRegistry`, call `ATTESTER.signBind` (Celo-gated) or, for a passport bound to another account, read `rebindCount` and call `ATTESTER.signRebind` (bundle `kind: 'rebind'`, decision 0022), and store the bundle in the per-account `BindBundleDO` Durable Object (decision 0010) for `GET /v1/self/bind-bundle/:account` (csa1-gated outside development). The endpoint must stay on the `cofferdam.xyz` host (zone route): only the host enters the immutable scope.
- `src/routes/ceremony.ts` + `src/services/ceremony.ts` issue the decision 0016 ceremony co-sign (`POST /v1/ceremony/first-high`): the gate is pure and tested against fakes; chain reads and the `ATTESTER.signCeremony` call are injected.
- `src/routes/aa.ts` + `src/services/userOp.ts` relay the app's signed ERC-4337 ops (`POST /v1/aa/user-operation`): policy (our paymaster, our factory in `initCode`, gas/fee/prefund caps) → `handleOps` simulation from the relayer → the per-sender `AA_RELAY_RL` → submission with `RELAYER_PRIVATE_KEY`. Like chat, the pickup, the ceremony and the relay run a global brake and a per-IP ceiling (`*_IP_RL`) first and count the per-account bucket only once their gate passes: account addresses are public. The first op of an account carries `initCode`, so this is also deployment (decision 0012).
- `src/routes/enterprise.ts` + `src/services/company.ts` + `src/services/companyLinks.ts` implement the domain-anchored `companyAnchor` resolver and `CompanyConsumerLink` grants. Link routes return `503 link_store_unprovisioned` until the `LINKS` KV namespace is created.
- `src/services/chat/facts.generated.ts` is the product-facts block the answer models' system message carries (workspace decision 0048), compiled from the workspace's `skills/*/SKILL.md` by `scripts/compile-skills.mjs` (run it and commit the output whenever a skill changes); `test/facts.test.ts` fails on drift, on more than 800 prompt tokens, and on jargon or internal names in a fact.
- `src/services/inference` is the only way to Workers AI (`test/inference.test.ts` fails on `env.AI` anywhere else): op classes with model pins (`AI_PINS` KV, then `CHAT_*_MODEL` or `WORK_*_MODEL`, then the default), an `op:` tag per call, timeouts, and the strict gateway with no log when `AI_GATEWAY_ID` is set.
- `src/routes/work.ts` + `src/services/work/` are the Work parser's cloud executor (workspace decisions 0020 and 0021, `docs/product/engine.md`): `POST /v1/work/classify` (the document type, one `clef-flash` call on `work-classify`) and `POST /v1/work/extract` (one de-identified block into a `cofferdam.cv.v1` fragment on `work-extract`, then `work-extract-fallback`); `intent.ts` parses a hirer's sentence on `work-intent` (no route yet). `blocks.ts` re-checks every block before any hosted call and fails closed; `fields.ts` holds the typed fields, the request per model family (Clairic, Workers AI JSON mode, the OpenAI JSON-schema wrapper) and the span validation; names come from the block's placeholders, never from a model. Outside development both routes answer `503 strict_gateway_required` until `AI_GATEWAY_ID` is set (decision 0021 (f)). The gate and the caps are the chat's, in the chat's order; every call is metered to the account and `plane:global` with no turn, priced from `usage.neurons` when reported, else `MODEL_PRICES` (`meter.ts`). `test/work.eval.test.ts` (opt-in, `WORK_EVAL=1`) compares extractors on the synthetic fixtures in `test/fixtures/work/`; no real personal data enters the repository or a model.
- `src/routes/chat.ts` + `src/services/chat/` run one Cofferdam Cloud chat turn (`POST /v1/chat`, workspace decision 0037): a global brake and `CHAT_IP_RL`, csa1 and an active High gate remembered for five minutes (`authorityMemo.ts`, shared only with `/v1/work`), the per-account `CHAT_RL` after the gate, a `clef-flash` router (`router.ts`) and the routed models (`run.ts`: the everyday answer starts with the router and is held until it clears the turn; `choices` when unsure; the body's `tier: "thinking"` answers on `chat-reasoning`, DeepSeek V4.1 Flash at low effort, high above `CHAT_THINKING_HIGH_FLOOR` on Clef's reasoning score, with no early answer and one retry when the first attempt has sent nothing within 15 s), streamed as server-sent events. The text never reaches a log. Each finished turn is metered per account and month in `ChatUsageDO`, and per month and model beside it with the router left out (`chatUsageStore.ts` holds the SQL, run on `node:sqlite` in `test/chatUsage.test.ts`; `chatUsageDO.ts`; prices in `MODEL_PRICES` in `services/inference`) through `waitUntil`; `CHAT_MONTHLY_USD_CAP` (dollars of estimated cost, not tokens) refuses an account with `429 fair_use_cap` and `AI_MONTHLY_BUDGET_USD` (the plane-wide row `plane:global`, which every hosted AI op must also record to) refuses everyone with `503 ai_budget_reached`, both before any model call, and `GET /v1/chat/usage` answers the month, its `models` most-used first and what is left of the cap in dollars and estimated turns, behind the same gate.
- `xmtp/` is the XMTP operator (workspace decision 0042), three Workers that deploy on their own and are not the plane: `backend/` (the XMTP 8 backend container, `backend.toml`, ingress slot `INGRESS=off` until the inbound-TCP beta), `push-relay/` (decision 0040: sealed tokens, APNs alert or FCM data, no storage, no `console`, observability off; `test/xmtp/pushRelay.test.ts` enforces it) and `cleanup/` (hourly expired-envelope deletion; its retention vars mirror `backend.toml` `[retention]`, checked by `test/xmtp/config.test.ts`; `src/health.ts` checks the backend's schema first, stores it under the KV key `health`, skips the run until the tables exist, and answers `GET /health`, reachable only through `wrangler dev --remote`). The backend's database is a direct Postgres 17+ endpoint, never Hyperdrive or a transaction pooler; only `cleanup/` uses Hyperdrive. `XMTP_CLEANUP_PG_URL=postgres://…/xmtp_cleanup_test yarn vitest run test/xmtp` runs the cleanup SQL against a migrated XMTP schema. On a backend version bump re-check `cleanup/src/sql.ts` against its migrations.
- The planned Assignment service is generic, account-pseudonym keyed, local-first, and escrow-optional. Port structural behavior from OffshoreSync `WorkAssignment`/`ScheduleOverride`; do not import Mongo IDs or maritime social dispatch into the plane.

## Validation and deploys

- `yarn test`, `yarn typecheck` (the Worker, then the Worker plus tests through `tsconfig.test.json`) and `yarn lint` (typescript-eslint, type-checked; `eslint.config.mjs`) must pass. The Mac lanes (`src/routes/chat.ts`, `src/services/chat/*`, `src/services/inference/*`) are downgraded to warnings in `eslint.config.mjs` until they are cleaned on the Mac; delete that block then.
- Verify on-chain authority config matches SDK encoding before deploying.
- Deploys run only from the Mac with the workspace `.envrc` loaded (`direnv exec .. yarn deploy`), never from a cloud session; when a contract pin moves, deploy the attester first. Runbook: `docs/runbooks/cloudflare-deploys.md` in the workspace. `src/chain/deployments.ts` mirrors `base-contracts/deployments/baseSepolia.json`.
- Design: `docs/architecture/plane.md` in the workspace.
